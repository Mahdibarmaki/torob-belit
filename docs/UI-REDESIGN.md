## Searchable airport selectors (2026-10-15)

The origin and destination now use one controlled `AirportSelector` component. It reuses the date picker's native `Dialog`, header, close button, backdrop, shadow, radius, font and focus trap. A shared `.picker-dialog` class preserves the existing 420px maximum width and 20px content padding for both pickers. The date picker is centered on mobile, so airports remain centered too; neither picker receives a new bottom-sheet treatment or animation. Selected airports use the same brand surface as selected calendar days, with a check icon; keyboard highlights use the existing brand focus color.

The existing airport records and their order are unchanged. A separate, pure `searchAirports` helper matches city, airport name and IATA code, including partial queries, Persian/Arabic letter variants, diacritics and spacing. English transliterations are search-only aliases keyed to existing airport identities; they do not add or replace display metadata. Query text and keyboard highlights remain local draft state. Only choosing a listed airport calls the existing draft-query callback; closing, searching or finding no match cannot change the airport or submit a flight search. Airport swapping, validation and all date/passenger/search/data logic retain their existing contracts.

The editable search uses combobox/listbox semantics with `aria-activedescendant`, Arrow Up/Down and Enter, including an IME composition guard. Escape, the close button and backdrop use the existing dialog dismissal behavior. An explicit trigger ref guarantees focus returns to the correct airport button, including browsers where pointer clicks do not focus buttons. Desktop automatically focuses search; coarse-pointer devices wait for an explicit tap to avoid unexpectedly opening the software keyboard.

Only the airport results scroll; the search input and dialog header remain outside that scroll region. Existing dynamic viewport limits constrain the dialog. When a software keyboard shrinks or pans the visual viewport without resizing the page, a scoped `visualViewport` listener recenters and bounds this dialog within the remaining visible area. A 16px search-input font on small screens is an intentional accessibility exception to the compact input scale, preventing automatic iOS focus zoom. No new dependencies, airport records, provider requests or flight-domain changes are introduced.

Verification: TypeScript, ESLint, production build, **386 unit tests across 14 files** and **39 production-browser tests** pass. Eight focused browser cases cover Persian/English/IATA matching, unchanged selection while typing, empty results, airport swap, Enter/arrow navigation, IME composition, dismissal and focus return, focus trapping, selected colors/check icon, computed-style parity with the date picker, touch autofocus policy, independent result scrolling, and a simulated visual-viewport keyboard overlay. Existing flight, date, price, comparison, history and hero regression checks remain green.
