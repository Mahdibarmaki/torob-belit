## Safe failure categories

| Provider condition | Assistant state |
| --- | --- |
| Missing key/model | `unavailable` |
| HTTP 401 | `authentication` |
| HTTP 403/404 or invalid request/model settings | `configuration` |
| Recognized credit, spend or quota code/type | `quota` |
| Transient HTTP 429 or local usage guard | `limited` |
| HTTP 400 `invalid_json_schema`, malformed/invalid structured output | `invalid` |
| Network / provider server failure | `error` |
| Total deadline | `timeout` |
| Model refusal | `refused` |

The error reader is bounded to 64KiB. It inspects codes/types only; raw provider
messages and bodies never reach the client or logs. Every failure preserves
intent and yields no patch. Existing UI fallback and manual recommendations
handle the new safe states without visual/component changes. No automatic
retry, alternate-model request or simulated language result is used.
[Official error guidance](https://developers.openai.com/api/docs/guides/error-codes).
